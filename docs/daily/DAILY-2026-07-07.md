## 2. 根因分析

| 问题 | 根因 | 影响 |
|------|------|------|
| manifest 误用 `annotation_size` 作 infer | `_infer_from_manifest()` 在无显式 `infer_width/height` 时回退嵌套 `annotation.annotation_size`（如 640×360） | 货框缩放到错误空间，skeleton 仍在 852×480，碰撞命中率丢失约 45% |
| 货框二次缩放 | 缺少 `boxesAlreadyInfer` 检测 | `video_polygon` 已在 infer 空间时仍按 `annotation_size` 缩放 |
| legacy 标注尺寸 | 缺少 `effective_annotation_size` 覆盖 | 货框已缩放但 `annotation_size` 仍为原始大画布时缩放错误 |
| infer 与 skeleton 不一致无告警 | `resolve_infer_frame_size()` 不校验 skeleton 实际范围 | manifest 写错时静默产生错位特征 |

## 3. 实现内容

### 3.1 `src/analysis/annotation.py`

- 新增 `is_norm_polygon_valid()`：校验 `video_polygon_norm` 在 [0,1] 范围（对齐 visual-dps `isNormPolygonValid`）。
- 新增 `effective_annotation_size()`：legacy 数据检测，货框已在 infer 范围但 `annotation_size` 仍为更大原始画布时覆盖为 infer 尺寸。
- 新增 `boxes_already_in_infer_space()`：当 `annotation_size == infer` 且 polygon 在 infer 范围内时，直接使用 `video_polygon`，不二次缩放。
- 更新 `scale_polygon_to_frame()`：polygon 超出 `annotation_size` 时按 extent 兜底（对齐 visual-dps `_scale_polygon_to_frame`）。
- 更新 `build_box_index()` / `infer_polygon_points()`：统一走上述逻辑，输出 polygon 与 skeleton 同在 infer 空间。

### 3.2 `src/analysis/records.py`

- **删除** `_infer_from_manifest()` 对 `annotation.annotation_size` 的回退。
- infer 解析优先级：`manifest` 显式字段 → `skeleton.parquet` 列 → `annotation.json` 根字段 → pose 管线启发式（640×360 → 852×480）。
- 新增 `_skeleton_coordinate_extent()`：从 bbox/kpt 99 分位数估计 skeleton 实际坐标范围。
- 新增 `_align_infer_with_skeleton()`：infer 明显小于 skeleton 范围时自动修正并 `logger.warning`。

### 3.3 `tests/test_annotation_scaling.py`

新增/更新测试：

- manifest 嵌套 `annotation_size` 不得当作 infer
- 货框已在 infer 空间时不二次缩放
- legacy `annotation_size` 覆盖
- 错误 manifest infer 时 skeleton 校验修正
- 640×360 标注 → 852×480 infer
