## 1. 问题背景与根因（上午）

现场 pose 隔帧采集，训练侧用 `--feature-frame-stride N` 模拟采样密度。原实现中：

- stride 只减少 **训练样本行数**（`frames[::N]`）；
- `FeatureContext.frame_index` 仍为全量 parquet；
- `prior_frame(offset)` 按 **`frame_idx - offset`** 查历史，stride 跳过的中间帧仍可用于时序特征；
- `eval` / `benchmark` 评测默认全帧，与 stride 训练不对齐。

## 3. stride=2 多模型 benchmark（下午）

### 3.1 命令

```bash
python main.py benchmark \
  --data-dir data/data28/Train \
  --eval-data-dir data/data28/Test \
  --output models/stride2 \
  --feature-frame-stride 2 \
  --feature-config configs/stride2_skeleton.json \
  --models sklearn_rf sklearn_logistic sklearn_extra_trees \
    sklearn_gradient_boosting sklearn_hist_gradient_boosting \
    sklearn_ada_boost sklearn_svm_rbf sklearn_knn sklearn_decision_tree \
  --jobs 4
```

### 3.2 训练规模

| 项 | stride=1（历史 feature_benchmark） | stride=2（本次） |
|----|-----------------------------------|------------------|
| 源骨架帧 | ~65612 | ~65612 |
| 采样后帧 | 74715（过滤后） | 32809 → 过滤后 **37385** |
| 正样本帧 | 3560 | **1778** |
| 特征 | skeleton + rule | 同左 |

### 3.3 Test 集结果 Top（Macro-F1）

| 模型 | Macro-F1 | 取货 F1 | Recall | 货框 Micro-F1 |
|------|----------|---------|--------|---------------|
| **sklearn_rf** | **0.873** | 0.764 | 0.871 | 0.579 |
| sklearn_hist_gradient_boosting | 0.871 | 0.757 | 0.721 | 0.612 |
| sklearn_svm_rbf | 0.859 | 0.741 | 0.993 | 0.322 |
| rule_baseline | 0.625 | 0.281 | 0.198 | 0.863 |

对比历史 **stride=1** `feature_benchmark`（同特征、同 data28 划分）最佳 Macro-F1 **0.894**（hist_gb），stride=2 略降但在隔帧部署语义下更一致。`eval_report.extra.feature_frame_stride=2` 已确认评测对齐。

## 5. 使用注意

- 训练用了 `--feature-frame-stride N`，**eval / benchmark 必须传相同 N**；模型 artifact 暂不自动保存 stride。
- parquet **dense** + stride=N：模拟现场隔帧；parquet **已隔帧** 时用 stride=1，避免二次下采样。
- **irregular** parquet：train/eval 同 stride 仍对齐，但时间步长不均匀，不等于均匀隔帧。
- 规则基线 `rule_baseline` 评测仍全帧，与 ML stride 采样密度不同，仅作参考。
